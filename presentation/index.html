From friction to flow.

01 · Before AI

Manual setup.

  • I usually had 3–4 worktrees, all managed by me.
  • They covered production, development, and someone else’s PR.
  • The path stayed the same; I only checked out different branches.

02 · The setup problem

Setup wasn’t automatic.

  • Make sure Yarn dependencies were installed.
  • Make sure iOS pods were installed.
  • Find the right Metro instance and open its debugger.
  • I had a few setup scripts, but never enough time to finish the workflow.

03 · After AI

More worktrees.

  • With AI, agents worked on different things, so I started creating temporary worktrees.
  • Every new worktree had to be ready to run—with Yarn, pods, .env files, and the Android keystore.
  • The setup work multiplied with every worktree.

04 · Ratatui

Built with
Ratatui.

05 · Small improvements

Less switching.

  • Show the JIRA ticket next to the branch.
  • Open the Metro debugger from the dashboard.
  • Run multiple Metro instances at the same time.

06 · Native build cache

Build once.
Run again.

  • Reuse iOS and Android builds between worktrees.
  • Keep JavaScript connected to the selected worktree’s Metro.
  • Test and experiment faster.

07 · MCP

Agents use it too.

  • Agents can use the dashboard through MCP.
  • They use the same queues, checks, ports, and worktree rules.
  • Human and agent workflows are managed in one place.

08 · Demo

What I’ll show.

  • Select a worktree.
  • Start Metro.
  • Launch a cached build.
  • Trigger the same workflow through MCP.
