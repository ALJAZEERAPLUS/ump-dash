# Quick Task 260713-6rt: Open the selected worktree in Finder

## Goal

Add `f` to the existing `o` Open palette, display it as `finder`, and open the selected worktree directory in macOS Finder. Selecting `o>f` must immediately return the palette to the root, keep `update()` free of I/O, pass the worktree path as typed data rather than a shell-quoted command, and surface launch failures through app state. The Linux build and test target must remain supported with a clear unsupported-platform error instead of attempting a macOS command.

## Architecture Notes

- Add explicit `OpenFinder` / `OpenFinderFailed` actions and an `OpenInFinder { path: PathBuf }` effect. Do not reuse `OpenExternalEditor`, because editor-specific failure reporting and string commands would erase the Finder intent.
- Keep `src/app/update.rs` pure: it clears `palette_mode`, snapshots the selected worktree, and returns the typed Finder effect. It must not call `std::process::Command`, inspect the operating system, or shell-quote the path.
- Extend the domain-owned `ExternalCommandPort` with a Finder operation accepting `&Path`. `EffectRunner` interprets the effect through `Adapters::external_command`; only `src/infra/external_command.rs` constructs and runs the platform command.
- On macOS, invoke the system `open` executable with the worktree path as one direct argument, not through `/bin/sh -c`. On non-macOS targets, return a descriptive error without spawning a process so Ubuntu CI and Linux releases stay deterministic.
- The footer and help overlay already derive palette entries from `KEYBINDINGS`; adding one canonical binding should update both without UI-layer edits.
