# Quick Task 260623-k7w: Add existing-branch picker to worktree checkout command

## Goal

When the user runs the worktree checkout command (`+>c`), show the same branch picker used by the new-worktree branch flow so the user can choose an existing branch to check out as a worktree.

The git new-branch checkout command (`g>c`) must remain a direct "new branch name" prompt and must not use this picker.

## Tasks

1. Add regression tests for the worktree checkout flow:
   - `WorktreeAdd` should request remote branches instead of opening text input immediately.
   - confirming a branch should dispatch `Effect::AddWorktree` with the selected existing branch.
   - `g>c` should continue to prompt directly for the new branch name.

2. Implement the flow in the TEA update layer:
   - reuse `Effect::ListRemoteBranches` and `ModalState::BranchPicker`.
   - distinguish existing-worktree checkout from new-branch worktree creation using existing modal-stack state.
   - preserve existing new-worktree branch picker behavior.

3. Remove the incorrect `g>c` base-branch behavior:
   - keep `CommandSpec::GitCheckoutNew` as a single branch-name command.
   - keep `to_argv()` output as `git checkout -b <branch>`.
