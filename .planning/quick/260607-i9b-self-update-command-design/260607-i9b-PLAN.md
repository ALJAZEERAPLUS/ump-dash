# Quick Task 260607-i9b Plan

## Goal

Add `ump-dash update` as a pre-TUI self-update command for GitHub Release
binary installs, including release-note display, checksum verification, safe
archive extraction, and same-directory executable replacement.

## Tasks

### 1. Add pre-TUI CLI dispatch

files: `src/main.rs`

action: Parse initial args before terminal/logging setup. No args start the TUI,
`update` runs the updater and exits, `--version`/`-V` print the compiled
version, and unknown args print usage with a nonzero exit.

verify: `cargo test` compiles the binary entrypoint and manual inspection keeps
the dispatcher small.

done: Update/version/usage behavior happens before Ratatui terminal setup.

### 2. Implement self-update infrastructure

files: `src/infra/self_update.rs`, `src/infra/mod.rs`, `Cargo.toml`

action: Add an infra module that shells out to `gh`, selects non-draft
non-prerelease semantic releases newer than `CARGO_PKG_VERSION`, prints release
bodies oldest to newest, downloads the platform tarball and `SHA256SUMS`,
verifies SHA-256, validates/extracts only the `ump-dash` archive entry, refuses
source checkout builds and non-writable install dirs, and replaces
`std::env::current_exe()` through same-directory temp/backup renames.

verify: Focused unit tests cover pure selection, path, checksum, archive, and
replacement-path behavior. `cargo test self_update` and `cargo check` pass.

done: Runtime updater is outside the TUI reducer/runtime and never executes
downloaded content during verification.

### 3. Publish checksums and document usage

files: `.github/workflows/release.yml`, `README.md`, `RELEASING.md`

action: Generate and upload `SHA256SUMS` in the release workflow, then document
`ump-dash update`, the `gh` requirement, source checkout behavior, curated
release bodies, and checksum publishing.

verify: Inspect workflow/doc alignment and run `cargo check`.

done: Users and releasers have matching instructions for self-updates.
