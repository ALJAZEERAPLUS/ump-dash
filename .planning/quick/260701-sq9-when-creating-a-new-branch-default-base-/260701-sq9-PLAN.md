# Quick Task 260701-sq9: Default new-branch base to origin/rc-trunk

## Goal

When the user starts the new-branch worktree flow and the base-branch picker opens, pressing Enter without typing or moving should choose `origin/rc-trunk`. The user must still be able to type a filter or move the selection to choose a different base branch.

## Source Audit

| GOAL | New-branch base picker defaults to `origin/rc-trunk` on Enter | Task 1, Task 2 | COVERED |
| CONTEXT | Preserve architecture invariants: domain shape/policy, app reducer orchestration, infra side effects, UI render-only | Task 2 | COVERED |
| CONTEXT | Test-first implementation | Task 1 before Task 2 | COVERED |
| CONTEXT | Do not update `ROADMAP.md` | No task touches `ROADMAP.md` | COVERED |

## Architecture Notes

- Keep this as pure state selection: no infra work, no git probing, no process calls.
- Put the preferred base-branch policy in `src/domain/command.rs` as domain-owned pure policy.
- Use `src/app/update.rs` only to choose the initial `ModalState::BranchPicker.selected` value when `BranchesLoaded` arrives for `pending_new_branch_worktree`.
- Do not change `src/ui/modals.rs`; it already renders the selected index from `ModalState::BranchPicker`.

## Tasks

### Task 1 - Add the failing reducer regression

Files:
- `src/app/dispatch_tests.rs`

Action:
- Add a focused test near the existing branch-picker tests named `new_branch_base_picker_enter_defaults_to_origin_rc_trunk`.
- Drive the real reducer sequence: start with `AppState::default()`, call `update(&mut state, Action::WorktreeAddNewBranch)`, then call `update(&mut state, Action::BranchesLoaded(vec!["origin/main", "origin/rc-trunk", "origin/release"]))`, then call `update(&mut state, Action::BranchPickerConfirm)` without sending any filter, next, or previous actions.
- Assert the confirm step emits no effects, sets `state.modal_stack.pending_new_branch_base` to `Some("origin/rc-trunk".into())`, and leaves the modal as `ModalState::TextInput { prompt: "New branch name:", buffer: "", .. }`.
- Do not modify production code in this task.

Verify:
- `cargo test app::dispatch_tests::new_branch_base_picker_enter_defaults_to_origin_rc_trunk -- --exact` fails because the current reducer selects the first branch instead of `origin/rc-trunk`.

Done:
- The failing test proves that Enter on the new-branch base picker currently chooses `origin/main` when `origin/rc-trunk` is present but not first.

### Task 2 - Select origin/rc-trunk for the new-branch base picker

Files:
- `src/domain/command.rs`
- `src/app/update.rs`
- `src/app/dispatch_tests.rs`

Action:
- In `src/domain/command.rs`, add a domain-owned constant for the preferred new-branch base, `origin/rc-trunk`, and a pure helper that returns the index of that branch in a loaded branch list or `0` when it is absent.
- In `src/app/update.rs`, update `Action::BranchesLoaded(branches)` so `selected` is computed with that helper only when `state.modal_stack.pending_new_branch_worktree` is true. Keep the existing `selected: 0` behavior for the existing-branch checkout flow.
- Leave `Action::BranchPickerFilter`, `Action::BranchPickerNext`, `Action::BranchPickerPrev`, and `Action::BranchPickerConfirm` behavior intact so typing and manual selection continue to decide from the visible filtered list.
- Keep the reducer pure: no adapter calls, no filesystem checks, no git commands.

Verify:
- `cargo test app::dispatch_tests::new_branch_base_picker_enter_defaults_to_origin_rc_trunk -- --exact`
- `cargo test app::dispatch_tests::branch_picker`
- `make arch-lint`
- `cargo test`

Done:
- Starting the new-branch worktree flow opens the branch picker with `origin/rc-trunk` selected whenever that branch exists in the loaded remote branch list.
- Pressing Enter immediately stores `origin/rc-trunk` as `pending_new_branch_base` and opens the new branch name text input.
- Existing worktree checkout still defaults to the first loaded branch.
- Filter and arrow-key selection behavior remains driven by the existing branch picker actions.
