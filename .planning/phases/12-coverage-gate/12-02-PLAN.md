<objective>
COVER-02 — Lock in the characterization that a Tokio `Command` launched with `.process_group(0)` can be reaped TREE-WIDE (parent + all children in the new PGID) by `libc::kill(-pgid, SIGTERM)`. This is the mechanism underlying Phase 15's TASK-04 per-task cancellation. If the mechanism ever regresses — for example if a Tokio upgrade silently changes when `setpgid` fires, or a developer removes `.process_group(0)` thinking it's redundant — this test fails in under 2 seconds.

Purpose: the test is deliberately adversarial. The bash fixture `trap "" SIGTERM; sleep 30 & wait` IGNORES SIGTERM at the parent level. A signal sent to only the bash PID (not the PGID) would be absorbed and `wait` would block until sleep exits naturally after 30 seconds — causing the test to time out and FAIL LOUDLY. Only a PGID-targeted signal can terminate `sleep` (which has no SIGTERM handler), which then breaks bash's `wait` call, which then allows bash to exit. This shape of fixture is the load-bearing detail that distinguishes "process-group kill actually works" from "we killed the parent and got lucky".

Output: a single `#[tokio::test(flavor = "multi_thread")]` function in `tests/process_group_kill.rs`, gated `#[cfg(any(target_os = "linux", target_os = "macos"))]`, completing in < 2.5 seconds.

**Important:** The research notes `infra/command_runner.rs` does NOT currently set `.process_group(0)` — only `infra/process.rs` does. This test therefore spawns `tokio::process::Command` DIRECTLY, not via `CommandRunner`. The `CommandRunner` process_group gap is a Phase 13 refactor concern and is NOT fixed here (see Deferred in 12-RESEARCH.md Pitfall 6).
</objective>

    ```rust
    //! COVER-02 — characterization of POSIX process-group kill.
    //!
    //! This test spawns `bash -c 'trap "" SIGTERM; sleep 30 & wait'` via
    //! `tokio::process::Command::process_group(0)`, then sends SIGTERM to the
    //! PGID (not just the PID). The bash parent IGNORES SIGTERM due to the
    //! `trap ""`, BUT the sleep child does not — sleep dies, bash's `wait`
    //! returns, bash exits. If `.process_group(0)` were absent or broken, only
    //! bash's PID would receive the signal, sleep would live for 30 s, and the
    //! 2-second `timeout(child.wait())` would FAIL the test.
    //!
    //! This adversarial fixture is the entire point: it can only pass if the
    //! PGID mechanism is working. See 12-RESEARCH.md §Pattern 3 for the full
    //! rationale.
    //!
    //! NOTE: this test spawns `tokio::process::Command` directly — NOT through
    //! `infra::command_runner::spawn_command_task`, because `command_runner.rs`
    //! does not currently call `.process_group(0)` (Pitfall 6 in 12-RESEARCH.md;
    //! flagged for Phase 13 refactor, not fixed here).

    #![cfg(any(target_os = "linux", target_os = "macos"))]

    use std::time::Duration;
    use tokio::process::Command;
    use tokio::time::{sleep, timeout};

    #[tokio::test(flavor = "multi_thread")]
    async fn killing_pgid_reaps_child_tree() -> anyhow::Result<()> {
        // Spawn the fixture. `trap "" SIGTERM` makes bash ignore SIGTERM; sleep
        // has no trap, so a PGID-targeted SIGTERM kills sleep, breaking wait.
        let mut child = Command::new("bash")
            .args(["-c", r#"trap "" SIGTERM; sleep 30 & wait"#])
            .process_group(0)       // THE invariant under test
            .kill_on_drop(true)     // defense-in-depth — reaps on test-body panic
            .spawn()?;

        let pgid: i32 = child
            .id()
            .expect("tokio::process::Child must expose pid before wait()")
            .try_into()
            .expect("child pid must fit in i32 on Linux/macOS");

        // Pitfall 3: kill(-1, ...) is a BROADCAST to every process of our UID.
        // Catastrophic on a dev machine. Assert we never ask libc to do that.
        assert!(pgid > 1, "refuse to kill(-1, ...): pgid = {pgid}");

        // Give bash ~100 ms to fork its sleep(30) child and join the PGID.
        // Without this, we might send SIGTERM BEFORE sleep has joined the group,
        // failing to exercise the full invariant.
        sleep(Duration::from_millis(100)).await;

        // Probe: pgid group must have at least one member at this point.
        // kill(pgid_negated, 0) returns 0 if group non-empty, -1 with ESRCH otherwise.
        // SAFETY: libc::kill is a POSIX syscall with well-defined behavior; we
        // validated pgid > 1 above.
        assert_eq!(
            unsafe { libc::kill(-pgid, 0) },
            0,
            "pgid {pgid} group should be live before we send SIGTERM"
        );

        // THE OPERATION: SIGTERM to the entire PGID. Bash ignores it (trap) but
        // sleep does not — sleep dies, bash's wait returns, bash exits.
        // SAFETY: same as above; pgid is our own child's pgid, owned by this UID.
        let kill_rc = unsafe { libc::kill(-pgid, libc::SIGTERM) };
        assert_eq!(
            kill_rc, 0,
            "libc::kill(-pgid, SIGTERM) should succeed; errno would be in *__errno_location()"
        );

        // Wait with a hard ceiling. If PGID kill is broken, this hits 2 s and
        // fails the test loudly with a clear message.
        let status = timeout(Duration::from_secs(2), child.wait())
            .await
            .map_err(|_| anyhow::anyhow!(
                "COVER-02 FAILED: bash parent + sleep child did not exit within 2 s \
                 of SIGTERM to PGID {pgid} — PGID-kill invariant is broken"
            ))??;

        // Parent bash exits with status 143 (128 + SIGTERM) on Linux; on macOS
        // `wait` in bash masks the signal, so exit code varies. Either success
        // or code 143 is acceptable — the LOAD-BEARING assertion is that it
        // exited at all within 2 s.
        let _ = status;  // status shape varies across bash/os — we only care that it exited

        // Final invariant: the PGID group is empty (ESRCH). Poll up to 500 ms
        // for the reaper to complete — faster than a fixed sleep on macOS where
        // waitpid-cascade ordering is not wall-clock bounded.
        let start = std::time::Instant::now();
        loop {
            // SAFETY: same as above.
            let probe = unsafe { libc::kill(-pgid, 0) };
            if probe == -1 {
                break; // ESRCH — group is empty, invariant holds
            }
            if start.elapsed() > Duration::from_millis(500) {
                panic!(
                    "COVER-02 FAILED: pgid {pgid} still has live members 500 ms after \
                     child.wait() returned — orphaned descendant detected"
                );
            }
            sleep(Duration::from_millis(20)).await;
        }

        Ok(())
    }
    ```

## STRIDE Threat Register

Phase 12 is a test phase; the security surface is near-zero because the test runs only during `cargo test` on developer/CI machines, the signal targets are exclusively our own spawned children, and no untrusted input crosses any interface. The register below exists because the security_enforcement gate requires documenting process-group-kill behaviors.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-02-01 | D (DoS — dev machine) | `libc::kill(-pgid, SIGTERM)` — if `pgid == 1` the call becomes `kill(-1, SIGTERM)` which broadcasts to every process of the current UID | mitigate | Explicit `assert!(pgid > 1, ...)` before any `libc::kill(-pgid, ...)` call. Value of `pgid` comes from tokio's `child.id()` for a child we just spawned — in practice always > 1. Pitfall 3 in 12-RESEARCH.md. |
| T-12-02-02 | R (Resource exhaustion — CI zombie accumulation) | tokio `Child` dropped without `.wait()` leaves a zombie; repeated flakes fill the process table on long-running CI | mitigate | Test body ALWAYS awaits `child.wait()` before returning; `kill_on_drop(true)` is a fallback, not a primary reap path. Pitfall 4 in 12-RESEARCH.md. |
| T-12-02-03 | T (TOCTOU — signal race) | PGID is read from `child.id()` at time T1; `libc::kill(-pgid, ...)` fires at time T2. If the child has already died and its PID has been recycled by another process in between, the signal could reach an unrelated group | accept | Probability on macOS/Linux with PID-namespace reuse: effectively zero within the sub-second test window (PID rollover requires ~32k forks on Linux, far more than happen in a 2 s test). Not worth the complexity of PID-refd cgroup attachments. Documented here, not guarded. |
| T-12-02-04 | I (Info disclosure — stray kill to non-child) | Same mechanism as T-12-02-01 but killing a sibling test's children if tests run concurrently and PIDs happen to collide | accept | `cargo test` default is multi-threaded test execution, so multiple tests can run concurrently. However, each test's PGID is uniquely allocated by the kernel at spawn time; no two live children share a PGID. Signal to `-pgid_A` cannot reach a child of `pgid_B`. Documented rather than guarded. |

**Severity:** all threats above are Low because: (a) the test only runs during `cargo test` (developer / CI machine; no production impact), (b) the signal targets are exclusively our own spawned children, (c) the PGID scope is kernel-enforced, and (d) `assert!(pgid > 1, ...)` eliminates the only truly catastrophic case (broadcast kill).
</threat_model>
